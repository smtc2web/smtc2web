smtc2web 源码深度解析
从系统媒体控制器到 OBS 实时显示主题 · 完整技术架构拆解
源码版本 v0.5.2 | Rust + Tauri 2.0 | Vue 3
项目概述
smtc2web 是一个基于 Rust + Tauri 2.0 的桌面应用，核心功能是 将系统媒体控制信息实时同步到浏览器主题，主要用于 OBS 直播场景。 用户在直播时，观众可以直接看到正在播放的歌曲信息。
Windows 使用 GlobalSystemMediaTransportControls API（事件驱动）
Linux 使用 MPRIS2 D-Bus 协议（轮询）
系统架构
SMTC / MPRIS ➞ media_worker ➞ Arc<RwLock<Song>> ➞ Warp HTTP API ➞ OBS / Browser
数据流向单向：媒体监听层 → 共享状态 → HTTP API → 前端主题渲染。 Tauri 管理 GUI 配置界面，Warp 作为独立 HTTP 服务器为 OBS 浏览器源提供服务。
核心技术栈
后端Rust + Tauri 2.0 + Warp HTTP + Tokio + Serde + once_cell
前端Vue 3 (Composition API) + Pinia + vue-i18n + vue-router + FontAwesome
媒体Windows: windows-rs (0.58) SMTC; Linux: mpris 2.0 D-Bus
构建Vite + pnpm + Tauri CLI + NSIS/DEB/RPM 打包
后端架构详解
媒体监听 — Windows SMTC
src-tauri/src/media/smtc.rs — 核心文件
基于 事件驱动 模型。通过 GlobalSystemMediaTransportControlsSessionManager 获取当前媒体会话，订阅三个事件：
1CurrentSessionChanged — 切换应用/歌曲（重建会话）
2PlaybackInfoChanged — 播放/暂停状态变化
3MediaPropertiesChanged — 标题/艺术家/专辑变化
4TimelinePropertiesChanged — 进度时间戳变化
WinRT 事件处理器被 Box::leak 泄露以绕过生命周期约束（注释标注 ponytail）。 专辑封面通过 TryGetMediaPropertiesAsync 获取缩略图流 → Buffer → base64 缓存。
AUMID Display Name 缓存
通过 PackageManager 解析 Store 应用显示名称，缓存到 HashMap 避免重复查询。
媒体监听 — Linux MPRIS2
src-tauri/src/media/mpris.rs — 轮询模型
使用 mpris crate 通过 D-Bus 查询 MPRIS2 播放器。 主动扫描所有播放器，按 Playing → Paused → Stopped 优先级排序选择。 播放时每 200ms 轮询，暂停时降为 1000ms。
专辑封面从 file:// 协议读取本地文件，base64 编码后缓存。 不支持 Snap/Flatpak 沙箱播放器（需要手动连接 D-Bus 接口）。
进程过滤
配置文件中的 process_filter 可指定只监听特定媒体应用，支持多行匹配。
专辑封面缓存系统
media/mod.rs 中维护全局 HashMap<String, (art, timestamp)>：
1每首歌生成唯一 ID：title|artist|album
2缓存命中直接复用，避免重复编码
3切换歌曲后 30s 内不重复抓取缩略图
4缓存上限 30 条，自动清理最旧条目
HTTP API 服务器
使用 warp 框架，默认监听 127.0.0.1:3030：
GET /api/now → JSON(Song) 当前歌曲信息
GET /api/image.jpg → JPEG 专辑封面
GET /theme/* → 静态文件 主题资源
GET /* → 静态文件 默认主题页面
服务器支持 无中断热切换主题：切换时优雅关闭旧服务器， 用新主题路径启动新实例，通过 oneshot channel 控制生命周期。
主题系统
主题目录位于 ~/.config/smtc2web/theme/，每个子文件夹即一个主题。 使用 theme.toml 声明元信息：
# theme.toml
[smtc2web.theme]
name = "spotify"
version = "0.1.0"
author = "AkarinLiu"
screenshot = "screenshot.png"
内嵌默认主题（rust-embed 编译时打包 frontend/ 目录）。 自定义主题通过 ZIP 导入，验证 根文件夹 + theme.toml + [smtc2web.theme] 三级检查，防止目录遍历攻击。
配置管理
config.rs — TOML 配置文件，路径
~/.config/smtc2web/config.toml：
端口server_port: 3030 | address: 127.0.0.1
主题current_theme + ZIP 导入/删除
语言locale: zh-CN / en（双端同步）
过滤process_filter: 匹配媒体应用 AUMID
更新auto_check_update: 更新源由 Tauri updater 插件管理
使用 notify crate 文件监控，外部修改配置自动热加载。 启动时最小化至托盘：minimize_to_tray 配置项控制，启动后直接隐藏主窗口。
系统集成
1单实例 — Windows: CreateMutexW | Linux: named-lock
2系统托盘 — 显示窗口、打开网页、检查更新、退出（双击恢复窗口）
3关闭行为 — 点击关闭 → hide() 而非退出（后台驻留）
4Win11 圆角 — DWM API (DwmSetWindowAttribute) 让无边框窗口圆角
5自动更新 — 双源回退 + 版本比较 + NSIS 静默安装
托盘菜单支持切换语言后实时刷新，无需重启应用。 更新系统通过 reqwest 并行尝试 GitHub Release 和官网，任意源可用即可。
日志与国际化
日志 按日期分文件，30 天自动清理。提供 log_debug! / log_info! / log_warn! / log_error! 四个宏。
i18n Rust 端 TOML 语言包（托盘+CLI），Vue 端 vue-i18n JSON。 支持 zh-CN / en，自动检测系统语言。
前端架构详解
路由与状态管理
路由：/ → 重定向 → /themes（主题管理）和 /settings（设置）， 均 懒加载。使用 createWebHistory 模式。
Pinia Stores（Composition API 模式，共 5 个）：
config读写 Tauri 配置、启动时最小化至托盘
theme主题 CRUD、下载、ZIP 上传
locale双端语言同步（vue-i18n ↔ Tauri）
toast通知 + confirm 弹窗（防重叠）
update检查/下载/安装更新
组件树与设计风格
组件树结构（10 个扁平 UI 组件，2 个页面视图）：
App.vue
├── TitleBar — 自定义标题栏 + 导航 + 窗口控制
├── RouterView
│ ├── ThemesView — 主题网格 / 骨架屏 / 空状态
│ │ └── ThemeGrid → ThemeCard
│ └── SettingsView — 表单 / 骨架屏 / 字体扫描
│ └── LanguageSelector
├── Toast — Teleport body，6 种位置
└── UpdateDialog — Teleport body，更新弹窗
纯 CSS 基于 Fluent Design CSS 变量系统，无 Tailwind/Bootstrap。 暗色模式 通过 @media (prefers-color-scheme: dark) 自动适配。 每个组件 scope 样式，三态切换：骨架屏 → 空状态 → 数据视图。
开发模式
主题开发服务器 (dev)
smtc2web dev [path] 命令启动独立开发服务器：
1自动检测 vite.config，若存在则启动 Vite 反向代理
2文件监控 + SSE 热重载，无需手动刷新浏览器
3HTML 自动注入 SSE reload 脚本（__dev_reload）
4独立媒体监听 + API 服务器（不启动 GUI）
默认主题 (OBS Overlay)
内嵌于 src-tauri/frontend/，纯前端 Vue 3 + CSS。 每 1s 轮询 /api/now，播放时动态缩短到 100ms 间隔。 支持 自定义字体：通过 font_family 配置注入 CSS 变量。
Spotify 风格 毛玻璃背景 + 绿色进度条 + 圆角封面。 为视频博主直播"正在播放"场景优化设计。
完整数据流
[Windows SMTC / Linux MPRIS2]  →  media_worker → Shared<Song> (Arc/RwLock) → Warp HTTP (/api/now) → OBS Browser Source / Web Page
